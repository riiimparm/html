Claude Codeで仕事を完結させるハーネス集

作成日: 2026-11-03 ／ 対象: 仕事PCでは Claude Code しか使えない人 ／ スター数は 2026-11-03 時点の GitHub API の値

解きたい悩み：やることが多くて集中できない。朝「何から手を付けるか」で迷う。仕事PCではGrok Botが使えず、Claude Codeの中で完結させたい。
結論：①タスクの置き場をClaude Codeから読める形にする（TASKS.md か TickTick/GitHub MCP）→ ②朝に「今日の3件」を決めるコマンドを1つ持つ → ③作業中は1件に絞り、hooksで毎回それを思い出させる → ④終わりに振り返って明日の1件目を決めておく。この4段を下のハーネスで組みます。

2. タスク台帳と「朝の棚卸し」

Anthropic Productivity プラグイン

おすすめ★ 34,462（anthropics/knowledge-work-plugins）公式

できること作業ディレクトリの TASKS.md（Active / Waiting On / Someday / Done）を Claude が読み書きする。人・プロジェクト・社内用語を覚える2層メモリ（CLAUDE.md＋memory/）と、TASKS.mdと同期するローカルHTMLダッシュボード付き。主にCowork向けだが Claude Code でも動くと明記されている。

悩みへの効き/productivity:update で古いタスクの棚卸しと期限切れの整理をする。「何が溜まっているか」を毎朝1コマンドで見られる。ファイルなので社外サービスに出さずに済む。

claude plugin marketplace add anthropics/knowledge-work-plugins
claude plugin install productivity@knowledge-work-plugins
# セッション内で
/productivity:start     # 初期化（TASKS.md, memory/, dashboard.html）
/productivity:update    # 毎朝: 棚卸し・期限切れ整理

注意: --comprehensive はメール・チャット等のコネクタ前提。仕事PCで外部連携が使えない場合は既定モードだけで十分。TASKS.md は機密を含みうるので公開リポジトリに置かないこと。

TickTick 公式MCP

公式リモートMCPStreamable HTTPOAuth / Bearer

できることTickTickのタスク検索・追加・完了・リスト操作をClaude Codeから行う。エンドポイントは https://mcp.ticktick.com。

悩みへの効き私用PC（Grok Bot）と仕事PC（Claude Code）で同じタスク台帳を見られる。タグ（#手続き・#勉強 など）で「今日やる分」だけ抜き出せる。

claude mcp add --scope user --transport http ticktick https://mcp.ticktick.com
# セッション内で /mcp を開き OAuth を完了

注意: 仕事のタスク名を個人のTickTickに書いてよいかは会社のポリシー次第。ダメなら仕事はTASKS.md、私用はTickTickと分ける。Bearerトークンを --scope project で登録すると .mcp.json にトークンが平文で入るので、使うなら既定（local）か user スコープで。

GitHub MCP Server

★ 34,167公式

できることIssue・PR・レビュー依頼・Actions を Claude Code から参照/操作する。リモート版は https://api.githubcopilot.com/mcp/。

悩みへの効き「自分にレビュー依頼が来ているPR」「自分に振られたIssue」を朝まとめて出させ、他人を待たせている物を先に片付ける判断ができる。

claude mcp add --transport http github https://api.githubcopilot.com/mcp/ \
  --header "Authorization: Bearer $GITHUB_PAT"

注意: PATは最小権限（fine-grained・対象リポジトリ限定・読み取り中心）で。会社がGitHub Enterpriseなら別エンドポイントや許可が必要な場合あり。

3. 着手判断と集中を支えるスキル集

pstack（poteto / Lauren Tan）

おすすめ★ 15,120（cursor/plugins）Claude Code 公式対応

できること設計・検証・根本原因・文章推敲などのスキル集。Claude Code用の導入手順がREADMEにあり、コマンドは /pstack:〜 の接頭辞付きになる。Cursor専用機能が要る手順は1行の注記でスキップされる。

悩みへの効き

  • /pstack:in-your-own-words … 着手前にゴールを言い直させ、ズレた作業に時間を溶かすのを防ぐ
  • /pstack:sharpen … 依頼を「大きく」ではなく「深く」する。手を広げすぎ防止
  • /pstack:poteto-mode … タスクをプレイブックに当てはめ、手順のToDoを作って進める
  • /pstack:ketchup … 進んだことと、自分の返事待ちを短くまとめる（中断からの復帰用）
  • /pstack:correct … 同じ指摘を繰り返さないよう、lint・テスト・スキルで仕組み化
/plugin marketplace add cursor/plugins
/plugin install pstack@cursor-plugins
/pstack:setup-pstack     # モデルと推論予算を選ぶ → ~/.claude/rules/pstack-models.md

代替: Claude向けに名前を事前変換し、SessionStartフックで自動ルーティングする移植版 michael-denyer/pstack-claude（★ 3,781、Claude Code 2.1.292以降）。スキルだけ選んで入れたいなら backnotprop/pstack（★ 3,404、npx skills add backnotprop/pstack）。

注意: サードパーティのマーケットプレイスは自動更新オフが既定。更新は claude plugin update pstack@cursor-plugins。本家と移植版を両方入れるとコマンドが重複するのでどちらか一方に。

Superpowers（obra / Jesse Vincent）

★ 311,106公式マーケットプレイス掲載

できることTDD・デバッグ・計画などのスキル集。/brainstorm → /write-plan → /execute-plan の流れと、SessionStartでのコンテキスト注入を持つ。

悩みへの効き「ふわっとした仕事」を brainstorm で要件化し、plan で小さな手順に割ってから実行する型が手に入る。最初の一歩が小さくなるので着手しやすい。

/plugin install superpowers@claude-plugins-official

注意: pstackと役割が重なる（計画・TDD・デバッグ）。両方入れるなら「計画はSuperpowers、検証と推敲はpstack」のように使い分けを決めておく。

4. Claude Code の標準機能で組む「集中の仕組み」

hooks（SessionStart / UserPromptSubmit）

おすすめ標準機能

できることSessionStart はセッション開始・再開・compact時に走り、標準出力がコンテキストに入る。UserPromptSubmit は毎回のプロンプト送信時に additionalContext を差し込める。

悩みへの効き「今やっている1件（NOW.md）」をセッション開始時に必ず読ませる。脱線しかけたらClaude側から「今の1件はこれです」と戻してくれる。

// ~/.claude/settings.json（抜粋）
{
  "hooks": {
    "SessionStart": [
      { "matcher": "startup|resume|compact",
        "hooks": [ { "type": "command",
          "command": "test -f NOW.md && { echo '## 今の1件 (NOW.md)'; cat NOW.md; } || echo 'NOW.md がありません。まず今日の1件を決めてください。'" } ] }
    ]
  }
}

注意: hookは任意コマンドを実行する。他人のプラグイン由来のhookは中身を読んでから有効化する。

/loop とスケジュール実行

標準機能

できること/loop 25m … でセッション内のプロンプトを定期実行。「15時にリマインドして」のような単発リマインドも自然文で可。ローカルのタイムゾーンで動き、繰り返しタスクは7日で自動失効。

悩みへの効きポモドーロ風に25分ごと「NOW.mdの進捗を1行で聞く／脱線していたら戻す」をさせられる。

/loop 25m NOW.md の1件について、進んだことを1行で私に聞いて。別の作業をしていたら NOW.md に戻るよう促して。
remind me at 17:30 to run /productivity:update and decide tomorrow's first task

注意: セッションを閉じると止まる。セッションをまたいで毎朝動かしたいなら クラウドのスケジュール実行（ローカルファイルは見えない）かDesktopのスケジュール実行を使う。

CLAUDE.md ／ サブエージェント ／ 出力スタイル ／ ステータスライン

標準機能

CLAUDE.md~/.claude/CLAUDE.md に「1件ずつ」「脱線は PARKING.md に逃がす」などの働き方ルールを常駐させる（下のスニペット参照）。

サブエージェント調査や長いログ読みを別コンテキストに出し、メインの会話を「今の1件」だけに保つ。

出力スタイル/output-style で返答を短く保ち、読む負荷を下げる。

ステータスラインNOW.md の1行目を常に画面下に出すと、自分の目にも「今の1件」が入り続ける。

6. おすすめの組み合わせ

  1. 台帳：仕事は Productivity プラグインの TASKS.md（ローカル完結）。私用と共有してよい物だけ TickTick MCP。コード周りは GitHub MCP。
  2. 今の1件：NOW.md（1行〜数行）を作り、SessionStart フックで毎回読ませる。
  3. 着手前：重い仕事は /pstack:in-your-own-words でゴールを言い直してから。ふわっとした仕事は Superpowers の /brainstorm → /write-plan（入れるならどちらか主にする）。
  4. 作業中：/loop 25m で進捗確認。思いついた別件は CLAUDE.md のルールで PARKING.md に逃がす。調べものはサブエージェントへ。
  5. 終わり：/pstack:ketchup か /productivity:update で振り返り、明日の1件目を NOW.md に書いて終える。

7. 朝のルーティン例（Claude Codeで10分）

  1. claude を起動（SessionStart フックが NOW.md と昨日の続きを表示）
  2. /productivity:update … TASKS.md の棚卸し。期限切れは「今週やる／Someday に送る／捨てる」の3択で片付ける
  3. 次のプロンプトで今日を決める：
TASKS.md（とTickTickの「今日」・GitHubのレビュー依頼）を見て、今日やる3件を選んで。
基準: ①他人を待たせている物 ②期限が近い物 ③30分で終わる物を1件は入れる。
各件に「最初の5分でやること」を1行つけて。1件目を NOW.md に書いて。
  1. 1件目に /pstack:in-your-own-words をかけてから着手
  2. /loop 25m で集中タイマーを開始（上の例文）
  3. 夕方 /pstack:ketchup → 明日の1件目を NOW.md に書いて終了

8. CLAUDE.md に貼るスニペット

## 働き方（集中ルール）
- 作業は NOW.md に書いた1件だけ。別件を頼まれたら、まず NOW.md の件を続けるか聞く。
- 作業中に思いついた別件・気になった改善は実行せず PARKING.md に1行で追記する。
- 着手前に「ゴール」「完了の条件」「最初の5分でやること」を3行で確認する。
- 30分以上かかりそうなら、15〜30分で終わる単位に分けてから始める。
- 調べもの・長いログ読みはサブエージェントに任せ、結論だけ3行で返す。
- 1件終わったら TASKS.md を更新し、次の候補を最大3件だけ提示する（全部は並べない）。
- 返答は短く。選択肢を出すときは推奨を1つ明示する。

9. 共通の注意点

  • 会社PCでのプラグイン・MCP導入は社内ポリシーを先に確認する（特に外部SaaSへのタスク送信、PAT発行）。
  • プラグインはhookやコマンドを実行できる。導入前にリポジトリの hooks と commands を読む（ハードニング目線でいつもどおり）。
  • TASKS.md / NOW.md / PARKING.md は業務情報。公開リポジトリやdotfilesに含めない（.gitignore 推奨）。
  • スキルを入れすぎると選ぶこと自体が負担になる。まずは「台帳＋NOW.md＋朝の1プロンプト」から始め、足りない所だけ追加する。
